IMS Knowledge Graph — Core Concepts 01 / 04
Category vs Tier — Two Independent Dimensions
Every node carries both a type of knowledge and a level of importance — these are orthogonal axes, not the same thing.
🏷
Category
What role does this node play?
Category describes the nature and function of a node — how the AI should use it when building a response. Each type occupies a distinct position in the reasoning chain:
● Concept — WHAT
Broad domain topics & capabilities. Parent anchors that frame the whole answer.
● Pattern — HOW WE STRUCTURE
Repeatable blueprints & delivery models. The standard shape before local changes.
● Procedure — HOW WE EXECUTE
Step-by-step workflows & deliverables. Where the actual work happens.
● Variant — WHERE IT DEVIATES
Regional, legal or client overrides. Localises the standard without replacing it.
● Scenario — WHEN RISK OCCURS
Real-world cases & stress tests. Shows how the standard flexes under pressure.
● Rule — WHAT WE CANNOT DO
Non-negotiable limits & compliance guardrails. Restricts the AI to compliant pathways.
⚡
Tier
How important is this — and how loudly should it speak?
T1 Critical T2 High T3 Standard T4 Low T5 Info
Tier controls context weight — how prominently a node appears in the AI's reasoning regardless of its depth in the graph.
⬆ Depth Promotion
A node can sit 4 levels deep in the hierarchy yet carry T1 Critical. Without tier, the AI would only encounter it after traversing many parent nodes. With T1, it is surfaced immediately — promoted above its structural position into the primary context window.

In short: Category defines the role of each node in the reasoning chain (WHAT → HOW → LIMITS). Tier controls contextual weight — promoting critical knowledge above its structural depth. Graph structure provides both a vertical parent-child pathway for depth and horizontal secondary links for cross-domain relevance. Together they produce structured, prioritised, multi-dimensional context for AI-generated responses.

What changes between them?
Category = identical (both Procedure).

Tier = completely different.
T1 is mandatory context. T4 is optional enrichment. The AI sorts them accordingly.
Key insight: A query about "site safety" would return the T1 Procedure first and prominently. The archiving T4 Procedure would never appear in that answer — the tier filter prevents irrelevant noise entering the AI context window.

IMS Knowledge Graph — Common Question 04 / 04
Pattern vs Procedure — Aren’t They Both About “How”?
They both start with “How” — but they answer very different questions. The distinction is architecture vs action.
📌
Pattern
The Framework
A Pattern defines the shape and architecture of how something is organised — before any work begins. It’s the repeatable model you reach for when scoping a piece of work.
It answers…
“What is our standard approach for this type of engagement?”
Example
Cost Planning Framework
Defines that cost delivery is structured around early benchmarking → control estimate → Stage 3 definitive plan. This is the template applied to every cost management engagement. You could hand it to a new joiner and they’d understand the overall shape of the work — without knowing a single specific step.
💡 Abstract — describes structure, not Tuesday’s task list. Think of it as the stage the work is performed on.
▶
Procedure
The Workflow
A Procedure defines the specific steps you carry out within that framework — concrete, sequential, and actionable.
It answers…
“What exactly do we do, in what order, to complete this task?”
Example
Monthly Cost Report
Pull the programme → reconcile committed spend → update the forecast → apply variance commentary → submit by the 5th. These are the actual steps a team member follows. Specific, executable, in a defined order.
💡 Concrete — tells you what to do on Tuesday morning. Think of it as the performance on the stage.
🏛 Analogy — A Building Project
Pattern
“We follow RIBA stages for all construction projects” — sets the delivery structure
Procedure
“At RIBA Stage 3: run cost planning workshop → produce Stage 3 estimate → submit for approval” — the actual steps
🧠 Why both must exist in the graph
Without Patterns, all Procedures become a flat list with no sense of which delivery model they belong to. The AI knows how to run a tender evaluation but has no context that it sits within Procurement rather than Cost Management.

Without Procedures, the AI understands the shape of work but has no executable steps to reference when asked “what do we actually do?”

One Pattern typically has many Procedures beneath it — the Pattern is the container; the Procedures are the content.
🎯
If in doubt:   Pattern = “what shape does our delivery take?” (the container/framework)  —  Procedure = “what steps do we follow?” (the content/execution).   Both start with “How” — but Pattern is the architecture, Procedure is the action.
